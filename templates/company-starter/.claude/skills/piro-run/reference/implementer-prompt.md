# 実装サブエージェント プロンプトテンプレート

実装サブエージェント派遣時にこのテンプレートを使う。`[...]` を埋めて派遣する。
派遣前に `git rev-parse HEAD` をBASEとして記録しておくこと。

```
Subagent (general-purpose):
  description: "Implement Task N.M: [タスク名]"
  model: [必須。SKILL.mdのモデル選択に従う。省略するとセッション最上位モデルを継承してしまう]
  prompt: |
    あなたはタスク N.M「[タスク名]」を実装する。

    ## タスク内容

    まずタスクブリーフを読むこと: [BRIEF_FILE]
    ブリーフには (a)タスク全文と実装メモ、(b)満たすべきEARS要件(逐語)、
    (c)設計の該当セクション が入っている。**ブリーフが唯一の要件ソース**。
    spec全体(.kiro/specs/)を読みに行かないこと。

    ## 文脈

    [このタスクがプロジェクトのどこに位置するか、依存する先行タスクの
    インターフェース・決定事項を1-3行で]

    ## 始める前に

    要件・受け入れ基準・アプローチ・依存関係に不明点があれば、**作業を始める前に
    質問すること**。推測で進めない。

    ## 仕事

    1. ブリーフのEARS要件を満たすよう、タスクの指定どおりに実装する
    2. テストを書く(要件が検証可能な形で)
    3. 動作を検証する(修正中は対象の絞ったテスト、コミット前に関連スイート)
    4. コミットする
    5. セルフレビュー(下記)
    6. 報告する

    作業ディレクトリ: [DIRECTORY]

    ## コード構成

    - 既存コードベースのパターンに従う。タスク外のリストラクチャはしない
    - 作成中のファイルが設計の意図を超えて肥大化したら、自分で分割せず
      DONE_WITH_CONCERNS で報告する

    ## 行き詰まったら

    「これは手に負えない」と言って止まるのは常に正しい。悪い成果物はゼロより悪い。
    以下のときは BLOCKED か NEEDS_CONTEXT で報告する:
    - 複数の妥当な選択肢があるアーキテクチャ判断が必要
    - 提供された情報の外のコード理解が必要で、調べても晴れない
    - 自分のアプローチが正しいか確信が持てない

    何に詰まったか・何を試したか・どんな助けが要るかを具体的に書くこと。

    ## 報告前のセルフレビュー

    - ブリーフのEARS要件を全部満たしたか。取りこぼしはないか
    - 頼まれていないものを作っていないか(YAGNI)
    - テストは本物の挙動を検証しているか(モックの挙動でなく)。出力にノイズはないか
    - 名前は「何をするか」を正確に表しているか

    問題を見つけたら報告前に直す。

    ## レビュー指摘を受けたら

    修正したら、修正箇所をカバーするテストを再実行し、結果をレポートファイルに
    追記すること。レビュアーはテストを再実行しない。あなたのレポートがテストの証拠。

    ## 報告形式

    詳細レポートを [REPORT_FILE] に書く:
    - 実装したもの(BLOCKEDなら試みたこと)
    - テスト内容と結果
    - 変更ファイル
    - セルフレビューでの発見
    - 懸念点

    最終メッセージは15行以内で以下だけ:
    - **Status:** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
      (必ずこの4語のいずれかをそのまま書く。COMPLETED等の言い換え禁止)
    - 作成したコミット(短SHA+件名)
    - テスト結果1行(例: "14/14 passing, output pristine")
    - 懸念(あれば)
    - レポートファイルのパス

    BLOCKED/NEEDS_CONTEXTの場合は、具体的な内容を最終メッセージ自体に書くこと。
    確信のない成果物を黙って出さないこと。
```

**プレースホルダ:**
- `[BRIEF_FILE]` - 必須。コントローラがscratchpadに書いたタスクブリーフのパス
- `[REPORT_FILE]` - 必須。ブリーフと対で命名する(`task-N-M-brief.md` → `task-N-M-report.md`)
- `[DIRECTORY]` - 対象プロジェクトの絶対パス
