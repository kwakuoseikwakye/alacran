# 人間判断の2階層モデル

AI適合度を評価する際、「人間判断が必要かどうか」を二値判定（必要 or 不要）にすると粒度が粗すぎる。**判断には2階層あり**、これを分離すると AI活用の設計が綺麗になる。

## 階層1: 定型承認（ルーチン承認）

**定義**: 毎月・毎週など定期的に必ず人が Go/No-Go を押すステップ。法的責任・組織的責任で人間判断が必須だが、内容自体は定型的。

**例**:
- 給与計算結果の所長承認
- 振込FB送信前の最終承認
- 電子申請の送信ボタン
- 月次決算の取締役承認

**AI適合度**: 低（人が必ず押すため）
**ただしAIができること**:
- 承認待ち通知の自動生成
- 前月との差分サマリーの作成
- 過去の差戻し履歴の提示
- 異常値のフラグ付け

→ 人の承認時間を短縮できる（「判断材料の準備」をAIに任せる）

## 階層2: 例外判断（イレギュラー判断）

**定義**: 条件付きで発生する判断で、法律解釈・経験・属人ノウハウが必要。発生頻度は低いが、判断負荷は高い。

**例**:
- 給与差押え通知への対応方針判断
- 標準報酬月額の等級変更該当者の最終判定
- 行政からの補正要求への対応方針
- イレギュラーな顧客クレームの対応

**AI適合度**: 低（判断そのものは人）
**ただしAIができること**:
- 該当候補の自動検出
- 過去の類似事例の検索・提示
- 判断パターンの参考表示
- 修正案の下書き生成

→ 「判断する人の認知負荷」を下げる（探す・思い出すを代行）

## なぜ2階層に分けるのか

### 設計が変わる
- 階層1（定型承認）: **AIに承認画面を作らせる** 設計が筋（判断材料を可視化）
- 階層2（例外判断）: **AIに過去事例を検索させる** 設計が筋（記憶補助）

設計の方向性が違うので、同じ「人間判断必須」で括ると間違ったAI実装をしてしまう。

### 工数構造が違う
- 階層1: 毎月発生・短時間（数分〜30分）
- 階層2: 条件付き発生・中時間（30分〜数時間）

工数試算と削減見込みも分離すべき。

### 引継ぎ可能性が違う
- 階層1: マニュアル化しやすい（誰でも承認できる）
- 階層2: ベテランに依存（暗黙知が多い）

→ 引継ぎ・BCPタスクとして別途切り出すべきは階層2の側。

## タスクJSONでの表現

`requires_human_approval: true` の場合、`description` に判断レベルを明記する：

```json
{
  "id": "T10",
  "name": "[F-承認] 所長による最終承認",
  "description": "担当者→チェック者→所長の承認フロー（定型承認）",
  "requires_human_approval": true,
  "ai_fit": "低",
  "ai_role": "承認待ち通知・差分サマリー生成（最終承認は人）"
}
```

```json
{
  "id": "T04",
  "name": "[C-判断] 例外対応（差押え・等級変更）",
  "description": "差押え通知への対応、等級変更該当者の判定（例外判断）",
  "requires_human_approval": true,
  "ai_fit": "低",
  "ai_role": "対象候補の自動抽出・過去事例の提示（最終判断は人）"
}
```

## Step 4で確認する質問例

> 「人間判断が必要なステップが見えてきました。これらは2階層に分けられそうです：
>
> **定型承認（毎月必ず人が押す）**: F検算→所長承認、G送信前承認、E電子申請送信
> **例外判断（条件付きで人が判断）**: C差押え対応・等級変更判定、E補正要求対応
>
> この2階層を別タスクとして切り出しますか？ 切り出すと、AI適合度が綺麗に分かれます（定型承認のサマリー生成はAI、例外判断は人）」

## 切り出しの効果

10ブロック（A〜J）から、判断階層を分離することで17タスク程度に細分化される例：

| 元ブロック | 細分化後 |
|-----------|---------|
| C 計算 | C-定型／C-例外判断 |
| E 電子申請 | E-準備／E-定型送信／E-例外補正 |
| F 検算 | F-照合／F-定型承認 |
| G 出力 | G-生成／G-定型送信承認／G-配信 |
| J 事務所運営 | J-運営／J'-引継ぎBCP（例外判断） |

この粒度になると、ロードマップが明確に書ける：
- フェーズ1: AIに任せやすい部分（C-定型、E-準備、F-照合、G-生成、I記録）
- フェーズ2: AIで下書き・人が確認（A受領、D社保届、E定型送信、G配信、H顧客対応）
- フェーズ3: 人が判断する部分の補助（C-例外、E-例外、F-定型承認、G-定型送信承認、J'-BCP）
