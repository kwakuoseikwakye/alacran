# /digest

Per the decision in `docs/decisions/2026-07-03-obsidian-context-stock.md` (Decision RFC) §C,
app-dependent aggregation queries such as Dataview / Bases are forbidden inside the stock
(no fake green — to prevent confusing "it appears to be displayed" with "it has been verified").
As the alternative, this command **generates plain Markdown from results the agent has actually
scanned and aggregated**. The output is an aggregation result only; it is not the SSOT.

## How to proceed

1. Decide the period to aggregate. The default is "the last 7 days" (from today back to 6 days ago).
   If the user specifies a period, follow that.
2. Scan the following with Grep / Glob and collect notes whose frontmatter `created:` / `updated:` falls within the period:
   - `notes/company/**/*.md` (exclude anything under `digests/` from aggregation — avoid self-reference)
   - `notes/market/**/*.md`
   - `notes/clients/**/*.md`
   - `notes/sops/**/*.md`
   - `docs/decisions/*.md`
   - `docs/retros/*.md`
3. Glob `notes/inbox/` and count the unprocessed notes excluding `README.md` (those not yet processed by
   `/ingest-context inbox`). List individually any file older than 7 days (a naive warning equivalent to
   STOCK-03; formally building this into `scripts/verify.py` as a machine check is a Phase C task).
4. Check `observed_at:` in `notes/market/**/*.md` and list anything more than 90 days old as of today
   (a naive freshness warning equivalent to STOCK-05. Turning it into an RQT is likewise a Phase C task;
   this command runs ahead by doing only the date comparison).
5. Get today's date and Write to `notes/company/digests/<YYYY-MM-DD>-digest.md` using the following template:

   ```markdown
   ---
   type: digest
   status: active
   created: <YYYY-MM-DD>
   updated: <YYYY-MM-DD>
   tags: []
   ---

   > **This file is an aggregation result, not the SSOT.** The source data is the shelves under
   > `notes/`, `docs/decisions/` and `docs/retros/`. Do not edit this file directly.

   # Digest <YYYY-MM-DD> (period: <start date> - <end date>)

   ## New and updated notes

   ### company
   - <slug> - <title> (<created or updated>)

   ### market
   - <slug> - <title> (<created or updated>, observed_at: <date>)

   ### clients
   - <client slug>/<topic> - <title> (<created or updated>)

   ### sops
   - <slug> - <title> (<created or updated>)

   ### decisions / retros
   - <filename> - <title> (<created or updated>)

   (For a heading with nothing to report, write "None" explicitly; do not omit the heading itself)

   ## Unprocessed inbox

   - Count: <N>
   - Sitting for more than 7 days: <list of filenames, or "None">

   ## market freshness warnings (observed_at over 90 days)

   - <slug> (observed_at: <date>, <N> days elapsed)
   - Write "None" if there are none

   ## Next actions (suggested)

   - <If there is inbox backlog, suggest running `/ingest-context inbox`>
   - <If there are freshness warnings, suggest re-checking the `source` of those notes>
   ```

6. Create `notes/company/digests/` if it doesn't exist, then Write.
7. After generating, summarise the content for the user.

## Notes

- Aggregation is based on the Grep/Glob results at that moment. Do not re-aggregate or auto-update past
  digests (each digest accumulates as a record of one snapshot).
- `type: digest` is a value added to the type enumeration of the shared frontmatter schema in
  `.claude/rules/notes-touch.md`. If you update the RFC body (the type enumeration), consider separately
  whether a Decision is required.
- Do not copy real names or real amounts into the output (aggregate only the frontmatter and titles of the source notes).
