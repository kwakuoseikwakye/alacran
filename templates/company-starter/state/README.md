# state/ — the git-tracked home for business-cycle logs

Where the operational scripts in `scripts/cycle/` write out each team's persistent log.
Unlike `.gitignore`'d scratch files (`.env`, caches, etc.), **this is a git-tracked SSOT**.
It keeps cycle execution records, KPI snapshots, and session-handoff digests in a form that
KPI measurement (`definitions/kpi/`) and retrospectives (`definitions/retro/`) can later
aggregate over.

> Not required for the retreat exercises (`scripts/cycle/` is treated as advanced). Ships
> empty at first — only teams that start actually running cycles grow its contents.

## Layout (per team-id)

```
state/
├── README.md                                  # this file
├── cycles/
│   └── <team-id>/                             # e.g. ec-team
│       └── <YYYY-MM-DD>/                      # the cycle's start date (Monday, for weekly)
│           ├── cycle.jsonl                    # 1 line = 1 event (appended to by cycle-event.sh)
│           └── kpi.json                       # a KPI snapshot (generated by cycle-kpi-snapshot.py)
└── handoff/
    └── <team-id>/
        ├── <YYYY-Www>.jsonl                   # a weekly handoff digest (appended to by session-handoff.py)
        └── latest.jsonl                       # the most recent one
```

## What goes in it

| Path | What it is | Generating script | Canonical schema |
|------|--------|----------------|------------------|
| `cycles/<team-id>/<YYYY-MM-DD>/cycle.jsonl` | The cycle-execution log (append-only) | `cycle-event.sh` | `docs/templates/cycle-execution-log-schema.yaml` |
| `cycles/<team-id>/<YYYY-MM-DD>/kpi.json` | A snapshot of the 2 common KPIs | `cycle-kpi-snapshot.py` | Aggregates the same log as above |
| `handoff/<team-id>/<YYYY-Www>.jsonl` | The session-handoff digest | `session-handoff.py` | — |

## Operational notes

- **Git-tracked**: cycle logs are a company record, so commit and keep them (retained for
  the entire history).
- **team-id**: use the team_id from `org.team` in `definitions/ontology/company.yaml` (e.g.
  `ec-team`).
- **No confidential data**: don't write real names, real amounts, or credentials here
  (following the PII policy in `.claude/rules/definitions-touch.md` — confidential data goes
  in `secrets/`).
- **A filled-in complete example**: `examples/harukaze-ec/definitions/kpi/ec-team-kpi.yaml`
  is an example that references this `state/cycles/ec-team/...` as a data_source.
