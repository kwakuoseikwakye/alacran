イントロ
これは何？ — 30秒でわかる説明
⏱ 約3分 ▼

AIカンパニーとは、AI（人工知能）を「社員」のように働かせる、小さな会社のしくみです。

  1. あなた（社長）が、AIに「これをやって」と指示を出します。
  2. AIは指示のとおりに、資料を作ったり、計算したり、記録をつけたりします。
  3. 大事な判断（お金を使う、契約する）だけは、必ずあなたが最後にOKを出します。

このリポジトリ（=フォルダのかたまり）は、その会社のしくみのひな形（テンプレート）です。 たとえるなら「マンガ雑誌の投稿用原稿用紙」。枠だけ用意してあって、中身（あなたの会社の情報）は、これから一緒に書きこんでいきます。

登場人物は3人だけ

登場人物役わりたとえるなら
あなた社長。指示を出す人、最後にOKを出す人クラスの係を決める先生
Claude Code（クロード・コード）AI社員。指示を受けて実際に動く人まじめでよく働く新入社員
GitHub（ギットハブ）記録係。やることリストや作った書類をぜんぶ保管する場所クラスの黒板 + ロッカー
あなた（社長） │ 「これやって」 ▼ Claude Code（AI社員） │ 「できました」 ▼ GitHub（記録係の黒板） │ ぜんぶの記録がここに残る

なぜ「会社」なの？

「AIに毎回同じことを説明するのが面倒」「昨日どこまで話したか忘れた」「AIが勝手にやりすぎてこまる」—— これらは全部、「会社のしくみ」が無いから起こります。

🏢 会社らしいしくみ = AIが迷わないしくみ

会社には社内ルールがあるから新入社員が迷わない。引き継ぎノートがあるから担当が変わっても仕事がつづく。上司の承認があるから勝手にお金を使われない。このテンプレートは、これらを AI 用に用意した箱です。

1
しくみを知る
会社のしくみ — 大事な部品は5つ
⏱ 約5分 ▼

フォルダとファイルはたくさんありますが、本当に覚えるべき部品は5つです。

部品場所中身たとえ
① CLAUDE.md
会社の憲法		いちばん上のフォルダ「うちの会社はこういう決まりで動きます」というルールブック。Claude Code は仕事を始めるとき必ずこれを読みます学校の校則
② .claude/rules/
細かい社内ルール		.claude/rules/「Issue（お仕事チケット）を先に作ってね」「勝手に大きな変更しないでね」などの約束ごと部活のルール
③ definitions/
自社のデータ		definitions/あなたの会社の情報（お客さんは誰か、商品は何か）。最初は空っぽ。これから書きこんでいく場所社員名簿と商品カタログ
④ .claude/commands/
おまじない集		.claude/commands//define-company みたいな「よく使うおまじない」の作り方。ぜんぶで9個。使いたいときにボタンを押すだけ電子レンジのあたためボタン
⑤ HANDOFF.md
引き継ぎノート		いちばん上のフォルダ「きょうはここまでやりました。次はここからやってね」というメモ。セッションが終わるたびに、次の自分に手紙を書く感じリレーのバトン
💡 ポイント

この5つさえ覚えれば、あとは必要なときに調べれば大丈夫です。

2
しくみを知る
仕事の流れ（5ステップ）と 6つのお約束
⏱ 約5分 ▼

どんな仕事も、この5つのフェーズ（段階）をぐるぐる回すだけです。

① 定義 → ② 計画 → ③ 実行 → ④ 検証 → ⑤ 記録 │ ┌──────────────────────┘ ▼ 次のサイクルへ
フェーズやることたとえるなら
① 定義「うちの会社はこういう会社です」を書きだす名刺を作る
② 計画「今度これをやります」と GitHub に書く（お仕事チケット=Issue を作る）買い物リストを書く
③ 実行Claude Code と一緒に、実際に作業する買い物に行く
④ 検証「ちゃんとできてる？」を機械にチェックしてもらうレシートで金額を確認する
⑤ 記録「きょうはここまでやりました」と書き残す家計簿に書きこむ

小さな仕事（誤字を1文字直すだけ、など）は ① と ② を飛ばしてもOK。でも大きな仕事や、あとで取り消せない仕事は、必ず ① から順に通してください。

大事な6つのお約束

全部覚えなくても、最初は名前だけ知っておけば大丈夫。

お約束ひとことで言うと
Issue-First（イシューファースト）仕事は、まず GitHub にチケットを作ってから始める
HITL Gate（ヒットル・ゲート）お金・契約・取り消せない操作は、必ず人間がOKを出す
SSOT（エスエスオーティー）大事な情報は「1か所だけ」にまとめる
Scope Contract（スコープ・コントラクト）始める前に「どこまでやるか」を宣言する
偽緑禁止（にせみどり・きんし）「動いてないのに動いたフリ」をさせない
セッション引き継ぎ作業の終わりに、次の自分に手紙を書く
⚠️ とくに大事なのは HITL Gate（人間の承認）

AIは速いですが、お金を使ったり、大事なデータを消したりする前には、必ず一度立ち止まって、あなたに聞くようになっています。

3
しくみを知る
メモ箱（notes/）— 思いついたことを放りこむ場所
⏱ 約5分 ▼

会社には definitions/（社員名簿や商品カタログ）という「きちんとした書類棚」とは別に、 「メモ帳の棚」が用意されています。それが notes/（ノーツ）です。 商談のあと、移動中——ふっと「あ、これメモしておきたい」というときのための場所です。

あなたが自由に書いていいのは「メモ箱」だけ

  1. あなた（社長）が自由に書いていいのは notes/inbox/（メモ箱）だけ、と覚えてください。
  2. 書き方（format）を気にせず、走り書きでOK。「きれいに書かなきゃ」と気負わなくて大丈夫。
  3. 他の小部屋（会社の物語・他社情報・お客さんメモ・手順書）には直接書きこまない。そこは AI社員が整理してくれる場所だからです。

スマホやタブレットからも書ける

Obsidian（オブシディアン）という無料のメモアプリでこのフォルダを開くと、外出先からでもメモを落とせます。 Obsidian が無くても大丈夫——パソコンで開いたときに、スマホの純正メモからコピペで貼り付けるだけでもOK。 くわしい同期のしかたは notes/inbox/README.md に書いてあります。

放りこんだメモは、AI社員が整理してくれる

次に Claude Code と作業を始めたとき、このおまじないでメモ箱の中身を確認してもらえます:

/ingest-context inbox

AI社員は、メモに機密（実名・金額・パスワードなど）が混ざっていないかをチェックしてから、正しい小部屋へ整理してくれます。

メモの中身整理される先
自社の物語・戦略メモ「会社の物語」の棚（notes/company/）
他社・競合・市場のこと「他社情報」の棚（notes/market/）
お客さんとの商談メモ「お客さんメモ」の棚（notes/clients/）
作業の手順「手順書」の棚（notes/sops/）
💡 安心設計

メモ箱に7日以上放置すると、/verify（チェック機械）が「たまってるよ」と教えてくれます。つまり、あなたは「とりあえず放りこむ」だけでよくて、片づけは AI社員にまかせられます。

🚫 大事な注意 — メモ箱にも書いてはいけないもの

メモ箱は git（記録係の黒板）に載って保存されます。実名・金額・パスワードは、メモ箱にも書かないでください。認証情報は secrets/ という別の「金庫」へ（そこは黒板には載りません）。迷ったら secrets/ へ、と覚えておけば安全です。

道具をそろえて、起動する
⏱ 約20分 ▼

ステップ1. 道具をそろえる（買い物リスト）

道具何をするもの？どうやって入れる？
Git（ギット）ファイルの履歴を残す道具git-scm.com からダウンロード
Python 3（パイソン）チェックスクリプトを動かす言語python.org からダウンロード
Claude CodeAI社員本体Claude の月額プランに入って、公式サイトからダウンロード
GitHub アカウント記録係の黒板github.com で無料登録
GitHub CLI（gh）パソコンから GitHub をあやつる道具cli.github.com からダウンロード

確認のしかた — パソコンの「ターミナル」（黒い画面）を開いて、こう打ちます:

git --version && python3 --version && claude --version && gh --version

それぞれバージョン番号が出たら、その道具は入っています。「command not found」と出たら、まだ入っていません。

ステップ2. 自分のリポジトリを作る

  1. GitHub の画面で、このテンプレートの "Use this template" ボタンを押す。
  2. 必ず "Private"（プライベート）を選ぶ（あなたの会社の情報を扱うので、外に見えないほうが安全）。名前は好きな名前でOK（例: my-ai-company）。
  3. 自分のパソコンにコピー（clone、クローン）する:
git clone git@github.com:あなたのアカウント名/リポジトリ名.git && cd リポジトリ名

ステップ3. Claude Code を起動する

claude

Claude Code が起動して、あいさつしてきます。このとき自動で CLAUDE.md（会社の憲法）を読みます。あいさつの時点で、会社のルールが頭に入っています。

ステップ4. まず1回だけ、チェック機械を動かしてみる

/verify
💡 最初は「INFO」だらけで正解

「うちの会社、ちゃんとルールを守ってる？」を機械にチェックしてもらうおまじないです。最初はほとんど「INFO（まだデータが無いのでスキップ）」が出ます。それが正解です。これから中身を入れていくと、だんだん「PASS（合格）」が増えていきます。

ステップ5. 自社を定義する（いちばん大事!）

/define-company

Claude Code が、4つの質問を1つずつ聞いてきます:

  1. どんな問題を解決している会社ですか？
    例: 「近所のパン屋さんの、レシピ管理と在庫管理を楽にする道具を作っています」
  2. 主なお客さんは誰ですか？
    例: 「街の小さなパン屋の店長さん」
  3. どんな流れで価値を生み出していますか？
    例: 「レシピ入力 → 材料の在庫チェック → 発注アラート」
  4. 今、いちばん困っていることは何ですか？
    例: 「発注を人の勘でやっているので、材料が余ったり足りなかったりする」

急がなくて大丈夫。答えをもとに、definitions/ontology/company.yaml という「会社の名刺ファイル」を作ってくれます。

ステップ6. できあがった名刺を眺める

definitions/ontology/company.yaml を開いて、「これで合ってるかな？」と眺めてください。ちがうところは、その場で書き直しても大丈夫。この時点で、AI社員はあなたの会社のことを知っている状態になりました。

ステップ7. 最初のお仕事チケット（Issue）を作る

なにか小さな仕事をやってみましょう。Issue-First の原則にしたがって、先にチケットを作ります:

新しい Issue を作って: 「HANDOFF.md に自己紹介を追加する」

Claude Code が GitHub に Issue を起票してくれます。これで作業の予約ができました。

ステップ8. 作業する

今作った Issue の作業を進めて

Claude Code は、始める前にかならず「これを変えます、これは触りません」を宣言してから作業します（= Scope Contract のお約束）。あなたはそれを見て、OKなら「進めて」と答えるだけ。終わったら自動でコミット（=セーブ）してくれます。

ステップ9. 記録を残して終わる

/handoff

HANDOFF.md（引き継ぎノート）が更新され、「きょうはここまで。次はここから」というメモが残ります。次のセッションは、このノートを読むところから始めればOK。

🎉 おつかれさまでした

これで最初のサイクルが1周まわりました！

6
慣れる
3日目までにやるといいこと
⏱ 3日間 ▼

はじめの1〜3日で慣れるために、こんな順番で試すのがおすすめです。

日やること使うおまじない
1日目「ステップ1〜9」を通して1周まわす/define-company /verify /handoff
2日目大きめの仕事を Epic（親チケット）に分解してみる/create-epic
3日目大事な決めごとの記録を残す練習。メモを AI に質問されながら、きちんとした形で棚に直接しまう練習/decision /retro /stock-note
慣れてきたらこの1週間で増えたメモ・決めごとのまとめ（週報のようなもの）を AI に作ってもらう/digest

これで、5つのフェーズ全部を1回ずつ体験できます。体験しおわると、「あ、これはこう回すのか」というリズムがつかめます。

症状対処法
Claude Code がルールを守ってくれない気がする 「CLAUDE.md を読んだ？ 5フェーズと6原則を教えて」と聞いてみる。答えられればルールを知っています。答えられなければ CLAUDE.md を Read してもらいましょう
/verify が「FAIL」と言ってきた かならず中身を読む。「めんどうだから消しちゃえ」はNG（=偽緑禁止のお約束違反）。FAIL の内容をコピペして「これ、どうすれば直る？」と聞けば、直し方を教えてくれます
Claude Code が勝手にお金や契約のことをやろうとしている 止めてください。それは HITL Gate（人間の承認）が必要な操作です。「これは私が判断するから、止まって」と言えば止まります
何をどこに書けばいいのか、迷った CLAUDE.md の §4.5「コンテキスト地図」に「この情報はどこに置く？」の対応表があります

用語ミニ辞典

言葉意味
リポジトリファイルとその歴史をまるごと入れておく箱。GitHub にあるものと、パソコンにあるものが対になる
クローンGitHub の箱を、自分のパソコンにコピーしてくること
コミット作業のセーブポイントを作ること。あとから「ここに戻して」と言える
Issue（イシュー）GitHub 上の「お仕事チケット」。仕事の予約票
PR（プルリクエスト）「この変更をとりこんでいい？」というお伺い。Issue と組で使う
ラベルIssue に貼るタグ（例: phase:planning）。状態を表す
hooks（フック）Claude Code が特定のタイミングで自動で動かす小さな検査
CLI（シーエルアイ）パソコンの黒い画面（ターミナル）から命令を打つやり方
YAML（ヤムル）情報を整理して書くための文字のならべ方。人間もAIも読める
SSOTSingle Source of Truth。「大事な情報は1か所にだけ書く」というお約束
HITLHuman-In-The-Loop。「大事な判断は人間を通す」というお約束
RQTRequired Quality Test。scripts/verify.py が回してくれる自動チェックの正体
frontmatter（フロントマター）ノートの先頭につける名札。いつ書いたか・何のメモかを機械が読めるようにする
Obsidian（オブシディアン）メモを見たり書いたりできる無料アプリ。無くてもこのテンプレは全部動く

覚えておいてほしい、たったひとつのこと

このテンプレートに正解の中身はまだ入っていません。
入っているのは「入れ物」と「書き方の約束」だけです。
正解を作るのは、あなたです。そして、それを一緒に整理してくれるのが Claude Code（AI社員）です。

道具はそろった。あとは、あなたの会社を入れていくだけ。
